## Автоматический вход через Telegram Mini App

Когда пользователь открывает приложение как Telegram Mini App, оно должно автоматически залогинить его через данные Telegram — без экрана регистрации и без ввода email/пароля. Если открыто по ссылке `/c/:slug` — пользователь попадает в кабинет партнёра, иначе — в обычный кабинет клиента.

### Как это будет работать (для пользователя)

1. Пользователь запускает бота @med_gid_bot в Telegram и нажимает кнопку "Открыть приложение".
2. Telegram открывает наш сайт внутри Mini App и передаёт подписанные данные пользователя.
3. Приложение показывает короткий сплэш «Вход через Telegram…» и через 1–2 секунды пользователь уже внутри — с именем, аватаром и историей расшифровок.
4. Гостевые данные (расшифровки, сделанные до входа с этого устройства) автоматически привязываются к новому аккаунту.
5. Если открыт в обычном браузере — работает как сейчас (гость или обычный вход).

### Что будет создано

**1. Edge-функция `telegram-miniapp-auth`**
- Принимает строку `initData` от клиента.
- Проверяет HMAC-SHA256 подпись через `TELEGRAM_BOT_TOKEN` по алгоритму Telegram, отклоняет запросы старше 24 часов.
- Ищет пользователя по `telegram_id` в таблице `telegram_users` (уже существует). Если нет — создаёт нового `auth.users` через Admin API с email вида `tg_<telegram_id>@telegram.local` и случайным паролем, сохраняет `telegram_id`, `username`, `first_name`, `last_name`, `photo_url`, `language_code`.
- Возвращает сессию (`access_token` + `refresh_token`) через `admin.generateLink` типа `magiclink` с последующим `verifyOtp` внутри функции, либо через сохранённый пароль.

**2. Хук `useTelegramAutoAuth`**
- В `App.tsx` при загрузке проверяет `window.Telegram?.WebApp?.initData`.
- Если есть и пользователь ещё не залогинен — вызывает edge-функцию, получает сессию, делает `supabase.auth.setSession(...)`, затем вызывает `claim_guest_data(device_id)` для переноса гостевых записей.
- Показывает лоадер «Вход через Telegram…» пока идёт процесс.
- Скрипт Telegram Web App (`https://telegram.org/js/telegram-web-app.js`) подключается в `index.html`.

**3. Маршрутизация после входа**
- Если URL был `/c/:slug` — редирект на `/c/:slug` (партнёрский поток, поведение не меняется).
- Иначе — на главную `/` в роли обычного клиента.
- Партнёрская роль (админка партнёра) при входе через Telegram Mini App **не выдаётся** — партнёры продолжают входить через обычный email/пароль на `/partner/login`. (Иначе любой пользователь Telegram мог бы получить доступ к чужому кабинету партнёра.)

**4. Настройка BotFather (шаг для вас)**
После деплоя я дам инструкцию: в BotFather у @med_gid_bot задать Menu Button → Web App с URL опубликованного сайта (`https://analizpro.lovable.app` или ваш кастомный домен).

### Технические детали

- Секрет `TELEGRAM_BOT_TOKEN` уже сохранён — новых секретов не требуется.
- Таблица `telegram_users` уже есть; добавлю недостающие колонки миграцией только если их не хватит после проверки схемы.
- Email вида `tg_<id>@telegram.local` — служебный, не отсылаем на него письма; выключение email-подтверждения для этих пользователей делается через `email_confirm: true` в Admin API при создании.
- Функция `telegram-miniapp-auth` работает с `verify_jwt = false` (пользователь ещё не залогинен), но валидирует HMAC от Telegram — это защищает от подделки.
- Существующая функция `claim_guest_data(device_id)` используется без изменений.
- В обычном браузере (`window.Telegram.WebApp.initData` пустой) ничего не меняется — всё работает как раньше.

### Ограничения

- Автовход работает только внутри Telegram (Mini App / кнопка в боте / inline-кнопка Web App). По прямой ссылке из браузера — обычный поток.
- Telegram не всегда возвращает username и никогда — email пользователя. Аккаунт идентифицируется по `telegram_id`.
- Один Telegram-аккаунт = один аккаунт в приложении; связать его с уже существующим email-аккаунтом нельзя (по вашему выбору).
