

# Исправление скачивания PDF и отправки на мобильных устройствах

## Проблемы

1. **PDF на смартфоне**: `pdf.save()` скачивает файл в фоне без диалога выбора папки -- пользователь не понимает куда файл сохранился
2. **Кнопка "Поделиться"**: `navigator.share` может не поддерживаться или блокироваться в контексте iframe, и при ошибке пользователь ничего не видит

## Решение

### Изменение 1: `src/utils/exportReport.ts`

**PDF на мобильных** -- вместо `pdf.save()` создавать Blob и открывать через `navigator.share` (нативное окно "Поделиться") или через `window.open` с blob URL, чтобы пользователь сам решил что делать с файлом:

```
1. Генерируем PDF как Blob
2. Если доступен navigator.share с поддержкой файлов -- открываем нативный диалог "Поделиться" с PDF-файлом
3. Иначе -- открываем PDF в новой вкладке через blob URL (пользователь увидит PDF и сможет скачать/поделиться)
4. На ПК -- оставляем pdf.save() как есть
```

**Отправка изображения** -- аналогичная логика: если `navigator.share` недоступен, открываем изображение в новой вкладке вместо тихого скачивания.

### Изменение 2: `src/pages/Results.tsx`

- Кнопка "Скачать PDF" на мобильном будет открывать нативный диалог шаринга с PDF (пользователь может сохранить в Файлы или отправить)
- Кнопка "Поделиться" -> "Отправить как изображение" будет корректно вызывать нативный диалог
- Добавить опцию "Отправить PDF" в диалог "Поделиться"
- Улучшить обработку ошибок с понятными сообщениями

## Технические детали

В `exportReport.ts`:

- `exportAsPDF`: после генерации PDF вызывать `pdf.output('blob')` вместо `pdf.save()`, затем на мобильных использовать `navigator.share({ files: [pdfFile] })`, а как fallback -- `window.open(blobURL)` для отображения PDF в браузере
- `shareAsImage`: добавить fallback через `window.open(blobURL)` если `navigator.share` недоступен
- Новая функция `shareAsPDF`: генерирует PDF и сразу открывает нативный диалог отправки

В `Results.tsx`:
- Добавить кнопку "Отправить PDF" в диалог шаринга
- Импортировать новую функцию `shareAsPDF`
